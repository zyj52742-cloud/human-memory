# 架构说明

这份文档讲清楚：**代码怎么分层、数据长什么样、分数怎么算、状态怎么流转、要改哪里**。

---

## 一、分层

```
┌─────────────────────────────────────────────┐
│  接口层                                       │
│  chat_play.py（人用）  mcp_server.py（AI 用）  │
│  demo_*.py（演示）     bench.py（性能）        │
├─────────────────────────────────────────────┤
│  引擎层  memory_core.py                       │
│  存储、状态机、召回打分、情绪分析、迁移、导入导出  │
├─────────────────────────────────────────────┤
│  评判层  scoring.py                           │
│  情绪识别、七因子重要性、类型判定、衰减与余波     │
├─────────────────────────────────────────────┤
│  存储层  SQLite 单文件（零第三方依赖）           │
└─────────────────────────────────────────────┘
```

关键原则：**评判层不碰数据库，引擎层不写死规则**。要调分数只改 `scoring.py`，要加接口只改接口层。

---

## 二、数据模型

单表 `memories` 加两张辅助表。

### memories（核心）

| 字段 | 含义 |
|---|---|
| `id` | 主键 |
| `profile` | 角色分区（多角色隔离） |
| `content` | 自然语言的一句话 |
| `kind` | 九种类型：identity / boundary / grudge / preference / relationship / goal / habit / mood / emotion / event / fact |
| `importance` | 重要度 0~1，写入时算一次 |
| `weight` | 动态权重，被召回 +0.03，重复写入 +0.08，上限 1 |
| `status` | `active` / `dormant` / `superseded` / `deleted` |
| `pinned` | 钉住 = 永不沉底 |
| `trigger_terms` | 逗号分隔的唤醒线索词 |
| `valence` / `arousal` / `salience` | 情绪三维：效价 / 唤醒 / 冲击力 |
| `decay_class` / `half_life` | 衰减类型与半衰期（天） |
| `aftermath` | 余波期（天），0 表示没有余波 |
| `resolved` | 人工强制确认已化解（0/1） |
| `resolve_signals` | 说过几次“放下了” |
| `breakdown` | JSON，六因子明细，用于解释 |
| `created_at` / `updated_at` / `last_recalled` / `recall_count` | 时间与访问统计 |

### aliases

同义词映射（香菜 ↔ 芫荽），让召回不漏。

### events

操作日志：created / strengthened / recalled / slept / woke / pinned / superseded / resolved / deleted。

## 三、状态机

```
                 写入
                  ↓
              ┌────────┐
              │ active │ ←──── wake（手动或线索命中）
              └───┬────┘
        ┌─────────┼──────────┬─────────────┐
        ↓         ↓          ↓             ↓
    dormant   superseded   deleted      （自然衰减不停，
   （手动睡/    （态度反转)  （软删）       只是分数变低）
    长期不用）
```

- **active → dormant**：手动 `/sleep`，或长期不被召回（预留）
- **active → superseded**：同一对象、态度反转时，旧条目自动退出召回，**历史保留**
- **active → deleted**：手动删除，默认软删可查，`hard=True` 才真删
- **dormant → active**：线索相关性 ≥ 0.25 时自动唤醒，或手动 `/wake`

只查 `active` 和 `dormant` 参与召回，其余状态自然被排除。

## 四、分数怎么算

### 4.1 重要度（写入时一次）

```
importance = 0.25 基础
           + 0.28 × 自我参照
           + 0.30 × 情绪冲击（|效价| × 唤醒）
           + 0.12 × 社会关系
           + 0.10 × 身份目标
           + 0.10 × 状态持续（mood/emotion 类）
           + 0.08 × 新奇意外
           + 0.05 × 细节丰富
           ↑ 封顶 1.0
```

### 4.2 情绪识别

1. 词典匹配（约 95 个词，含口语）
2. 程度修饰：非常/特别 → 唤醒 ×1.35；有点/稍微 → ×0.55
3. 否定反转：不/没/别 + 情绪词 → 效价取反并衰减
4. 防误判：「特别」里的「别」不算否定

### 4.3 召回（每轮实时）

```
score = 0.45 × 相关性 + 0.25 × 重要度 + 0.12 × 时近性
      + 0.10 × 权重 + 0.08 × 情绪冲击

修正：休眠 × 0.35 ；钉住 + 0.25
门槛：相关性 < 0.10 且没钉住 → 丢弃
```

相关性 = `0.6 × 正向覆盖 + 0.4 × 反向覆盖`，中文按 2-gram 切词。

### 4.4 衰减与余波

| 类型 | 半衰期 |
|---|---|
| 心结 grudge | 36500 天 |
| 身份 identity / 边界 boundary | 3650 天 |
| 关系 relationship | 730 天 |
| 偏好 preference | 365 天 |
| 目标 goal | 180 天 |
| 习惯 habit | 90 天 |
| 情绪状态 mood | 21 天 |
| 情绪 emotion | 30 天 |
| 事件 event | 10 天 |

情绪冲击 ≥ 0.50 → 半衰期 ×2；≥ 0.25 → ×1.5。

余波期（影响持续多久）：`3 + 情绪冲击 × 8` 天，仅情绪事件有。

### 4.5 心结强度（多路证据）

```
strength = 1.0
         - 0.02 × 天数（最多 -0.60）
         - 0.18 × 说过的放下次数
         - 0.12 ×（之后情绪整体转正）
         + 0.08 × 反复提起次数（最多 +0.24）
```

`strength < 0.25` 视为实质化解。**没有任何单一信号能单独清零。**

## 五、写入流程

```
输入文本
  ├─ 空 / 噪声 / 问句 → 丢弃
  ├─ 化解信号（"都过去了"）→ resolve_signals +1，影响所有未化解心结，不新建条目
  └─ 正常
       ├─ scoring.score_text() 打分
       ├─ 候选粗筛（trigger_terms 交集）
       ├─ Jaccard ≥ 0.72 → 强化已有，不新增
       ├─ 同对象 + 效价反转 → 旧条目 superseded
       └─ 插入新条目
```

## 六、召回流程

```
query
  ├─ 分词 → 同义词扩展
  ├─ 查 profile 下 active/dormant
  ├─ 逐条算相关性（2-gram 交集）
  ├─ 低于门槛且未钉住 → 丢弃
  ├─ 综合打分 → 排序 → 取 top_k
  └─ 命中后：权重 +0.03；休眠且强命中 → 唤醒
```

## 七、性能设计

- **倒排索引** `memory_terms(term, memory_id, profile)`：召回先查词条拿候选 id，只对候选算相关性，不再全表扫描
- 建表/迁移**每进程只做一次**（`_INITIALIZED` 缓存）
- 复合索引 `(profile, kind, status)`
- 去重与冲突检测先按 `trigger_terms` 粗筛，避免全表逐条 tokenize
- 单文件 SQLite，WAL 模式，支持多进程读
- 单字情绪词（累/怕/烦/气…）额外入索引，解决 2-gram 切不出单字的问题

实测（1 万条记忆，本机）：召回 **10–45 ms**，写入约 12 ms/条，库约 20 MB。

## 八、要改哪里

| 想做的事 | 改哪 |
|---|---|
| 加/改情绪词 | `scoring.EMOTION_LEXICON` |
| 调六个因子权重 | `scoring.W_*` |
| 加记忆类型 | `scoring.KIND_LABEL` + `DECAY_HALF_LIFE` + `_classify_kind` |
| 调召回权重 | `memory_core.W_*` |
| 加 MCP 工具 | `mcp_server.TOOLS` + `call_tool` |
| 加体验命令 | `chat_play.main()` 的命令分支 |

## 九、已知边界

1. 中文按 2-gram 切，单字词（累、饿、疼）和跨词匹配会漏
2. 情绪识别靠词典，隐性表达抓不到
3. 冲突判定依赖 trigger_terms 重叠，同义表达可能漏判
4. 权重全部是先验值，没有用真实数据训练过
